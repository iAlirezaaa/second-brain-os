# معرفی فارسی Second Brain OS

> **مغزی محلی برای به‌خاطرسپردن، پیدا‌کردن، ارتباط‌دادن و تبدیل دانش به کار قابل‌سنجش.**

Second Brain OS پروژه‌ای متن‌باز و مستقل از سرویس‌های پولی است که حافظه شخصی، منابع، پروژه‌ها، وظایف، مهارت‌ها و ایجنت‌های هوش مصنوعی را به یک جریان کاری مشترک متصل می‌کند. هدف آن فقط پوشه‌بندی و نگهداری یادداشت‌ها نیست؛ هدف این است که اطلاعات قدیمی و جدید را به‌درستی بازیابی کند، میان آن‌ها ارتباط‌های غیرمنتظره پیدا کند و در اجرای کارها، نتیجه‌ای قابل‌بررسی ارائه دهد.

**نام عمومی:** Second Brain OS  
**نام موتور:** HADES  
**فلسفه:** محلی و قابل‌انتقال، سبک روی دستگاه ضعیف، توسعه‌پذیر روی GPU، با کنترل نهایی انسان.

## امکاناتی که واقعاً وجود دارند

- نگهداری دانش و پروژه‌ها در فایل‌های قابل‌خواندن و ساختار شماره‌گذاری‌شده.
- جست‌وجوی مبتنی بر متن، برخی مخازن SQLite و ذخیره درس‌های ثبت‌شده.
- اتصال ایجنت‌ها از طریق MCP و رجیستری ابزارها.
- CLI جدید برای ساخت جلسه، لیست کار، اضافه‌کردن تسک، ثبت شواهد و هندآف اجباری.
- نسخه اولیه ADHD برای یافتن ارتباط‌های واژگانی بین حوزه‌های متفاوت؛ این ارتباط‌ها فرضیه هستند، نه حقیقت تأییدشده.
- Twin World اولیه برای شبیه‌سازی تغییر وضعیت تسک و نمایش Diff تغییر فایل در حافظه؛ هنوز Sandbox واقعی اجرای کد نیست.
- اتصال اختیاری Laya برای پیشنهاد تصمیم‌های ساختاریافته؛ مدل و وزن‌ها به‌صورت پیش‌فرض نصب نشده‌اند.

## امکاناتی که هنوز باید تکمیل شوند

جست‌وجوی ترکیبی و گراف دانش زمان‌مند، احراز هویت مستقل ایجنت‌ها، اجرای موازی و پایدار چندایجنتی، Sandbox ایزوله، ترکیب و ارتقای تأییدشده Skills، بکاپ عملیاتی کاربر و رابط‌های موبایل/مرورگر به آزمایش و توسعه بیشتری نیاز دارند. سبزشدن CI به معنای کامل‌بودن این قابلیت‌ها نیست.

## شروع سریع — اولین جست‌وجوی آفلاین

پیش‌نیاز: **Git و Python 3.9 یا جدیدتر**. در ویندوز PowerShell، ابتدا `python --version` را بررسی کنید؛ اگر دستور `python` موجود نیست، با `py -3 --version` نسخهٔ نصب‌شده را چک کنید و پس از تأیید نسخه، به‌جای `python` از `py -3` استفاده کنید. در macOS و Linux ممکن است لازم باشد از `python3` استفاده کنید.

```bash
git clone https://github.com/iAlirezaaa/second-brain-os.git
cd second-brain-os
python scripts/kb.py ingest
python scripts/kb.py search "memory"
```

دو دستور آخر، فایل‌های Markdown مخزن را در یک ایندکس محلی جست‌وجوپذیر می‌کنند و نتیجهٔ متنی همراه با مسیر فایل نشان می‌دهند. ایندکس در `.kb/kb.sqlite` ساخته می‌شود و در Git ثبت نمی‌شود. پس از Clone، این دو دستور نیازی به حساب کاربری، مدل زبانی، کلید API یا اینترنت ندارند. این قابلیت **جست‌وجوی کلیدواژه‌ای** است، نه بازیابی معنایی یا تضمین صحت پاسخ.

هدف تجربهٔ کمتر از پنج دقیقه است، اما زمان کامل Clone تا اولین نتیجه در Windows/macOS/Linux هنوز به‌صورت مستقل اندازه‌گیری و تأیید نشده است. برای آزمایش جداگانه با یادداشت ساختگی، `python scripts/first_success.py --repeat 3` را اجرا کنید؛ این آزمون زمان Clone را شامل نمی‌شود.

برای سنجش مستقل مسیر نصب یک حافظهٔ محلی، از پوشهٔ منبع دستور
`python scripts/first_success.py --installed-home --repeat 1` را اجرا کنید.
خروجی JSON مدت نصب، ساخت یادداشت ساختگی، ایندکس و جست‌وجوی کلیدواژه را
می‌سنجد؛ علاوه بر مسیر نتیجه، ردیف‌های واقعی SQLite، متن دو یادداشت
ساختگی و سازگاری تعداد ردیف‌ها با گزارش ایندکس را هم کنترل می‌کند.
زمان سنجش شامل همین اعتبارسنجی SQLite هم هست؛ اگر بررسی بعد از مهلت
مشترک آزمون پایان یابد، نتیجه شکست با دلیل timeout است. زمان انتظار قفل
SQLite محدود می‌شود، اما این تضمین توقف سخت‌افزاریِ دیسک نیست.
Clone و زمان ویرایش انسان در این عدد نیستند. CI این سنجش ساختگی را
روی Windows و Ubuntu اجرا می‌کند و یک Job محدود macOS 15 / Python 3.12
علاوه بر نصب و بازیابی ساختگی، تست‌های موجود شروع کار و کنترل ترتیب
راهنمای فارسی/انگلیسی و متغیرهای محیطی آزمایشی را نیز اجرا می‌کند.
این تغییر هنوز به CI نهایی همان کامیت نیاز دارد؛ هیچ‌یک از این نتایج
به‌معنای اجرای کل تست‌های macOS، اندازه‌گیری زمان Clone یا تضمین
عملکرد دستگاه کاربران نیست.


برای سنجش زمان **کلون محلی Git تا اولین نتیجه**، از پوشهٔ مخزن دستور
`python scripts/clean_checkout_recall.py` را اجرا کنید. این ابزار، یک
کلون موقت از فایل‌های کامیت‌شده می‌سازد، ایندکس و جست‌وجوی واقعی را اجرا
می‌کند و علاوه بر وجود ردیف‌های SQLite، وجود واژهٔ `memory` در عنوان یا متن نرمال‌شدهٔ هر ردیف را بررسی می‌کند؛
همچنین مستقل از SQLite، وجود این واژه را در متن Markdown کامیت‌شده یا نام
فایل منبع تأیید می‌کند و مسیر بیرون از کلون موقت را نمی‌خواند. خروجی JSON
زمان کلون محلی، ایندکس، جست‌وجو و زمان کل را با دلیل شکست نشان می‌دهد.
عنوان، متن کامل و شکل نرمال‌شدهٔ هر ردیف SQLite نیز با Markdown
کامیت‌شده و قواعد Frontmatter پروژه تطبیق داده می‌شود؛ صرف وجود مسیر
و کلمهٔ جست‌وجو، شاهد بازیابی نیست.
این عدد **شامل دانلود از GitHub، نصب Python، نوشتن یادداشت توسط انسان یا
راه‌اندازی واقعی کاربران نیست** و هنوز شاهد موفقیت کامل زیر پنج دقیقه
نیست. این تغییر در PR پیش‌نویس است و منتشر نشده است. در CI پیشنهادی،
همین سنجش محلی برای چهار ترکیب Ubuntu/Windows با Python 3.9/3.12 و
Job اختصاصی macOS 15 تنظیم شده است. فقط اجرای تکمیل‌شدهٔ همان کامیت
شاهد معتبر است؛ دانلود از شبکه هنوز سنجیده نمی‌شود.

این ابزار **پیش از ایندکس‌کردن** فهرست فایل‌های نسخهٔ کامیت‌شدهٔ Git را
ثبت می‌کند. یادداشت Markdown که هنگام اجرای ایندکس‌ساز ساخته شده باشد،
حتی اگر خروجی جست‌وجو و SQLite با آن سازگار باشند، شاهد بازیابی از
نسخهٔ کامیت‌شده نیست و با `no_source_backed_hit` رد می‌شود. خطای خواندن
فهرست Git با `tracked_paths_unavailable` گزارش می‌شود. این کنترل برای
صحت بنچمارک است، نه محدودکردن ساخت یادداشت در استفادهٔ عادی.

این ابزار آزمایشی پیش از اجرای فایل `scripts/kb.py` و خواندن
ایندکس SQLite، مسیرهای پیوندیِ `scripts/`، `scripts/kb.py`،
`.kb/` و `.kb/kb.sqlite` را با دلیل `unsafe_checkout_path`
رد می‌کند. هدف، جلوگیری از دنبال‌کردن مسیر بیرون از کلون موقت است؛
این کنترل **Sandbox امنیتی سیستم‌عامل نیست** و هنوز منتشر نشده است.
منبع Markdown نتیجه نیز نباید از پیوند نمادین یا Junction عبور کند؛
حتی اگر مقصد داخل کلون باشد. مثلاً مسیر ظاهراً عمومی `02_WIKI/`
نباید برای اثبات نتیجه، متن محدودشدهٔ `09_OPERATIONS/` را بخواند.
این صرفاً اعتبارسنجی محتاطانهٔ نتیجهٔ آزمایشی است، نه ایزوله‌سازی فرایند.
مقایسهٔ ردیف SQLite با متن منبع نیز مستقل از بررسی واژه، همین کنترل
مسیر عمومی و بدون پیوند را اجرا می‌کند؛ یک بررسی قبلی مجوز خواندن مسیر
محدود یا پیوندی در مرحلهٔ بعد نیست. این کنترل در برابر تغییر هم‌زمان
فایل‌ها تضمین اتمی ندارد و Sandbox محسوب نمی‌شود. تغییر هنوز منتشر نشده است.


**الزام تمیزبودن مخزن منبع:** سنجش در صورت وجود تغییرِ کامیت‌نشده
(فایل ویرایش‌شده، تغییر مرحله‌بندی‌شده یا فایل جدید غیرنادیده‌گرفته‌شده)
با دلیل `source_dirty` متوقف می‌شود؛ زیرا کلون محلی این تغییرات را
منتقل نمی‌کند و نتیجه به‌اشتباه نسخهٔ قدیمی را می‌سنجد. ابتدا تغییرات
را کامیت کنید یا از یک worktree تمیز استفاده کنید. ایندکس نادیده‌گرفته‌شدهٔ
`.kb/` باعث رد آزمون نمی‌شود. خروجی `preflight_ms` زمان کنترل وضعیت
Git را جدا می‌کند؛ `clone_ms` شامل کلون، تشخیص SHA و خواندن فهرست فایل‌های HEAD است و زمان کل هر
دو را دارد. برای منبع غیرقابل‌بررسی، دلیل `source_status_unavailable`
گزارش می‌شود. این کنترل صرفاً برای صحت بنچمارک است؛ نه محافظت یا بکاپ داده.
تغییر هنوز در PR #145 در دست بازبینی است.

برای سنجش تکرارپذیری با کلون‌های موقت مستقل، دستور
`python scripts/clean_checkout_recall.py --repeat 3` را اجرا کنید
(بین ۱ تا ۵ آزمایش، پیش‌فرض ۱). JSON نتیجهٔ تک‌تک آزمایش‌ها، تعداد
موفقیت‌ها، نرخ موفقیت، میانهٔ زمان **با احتساب شکست‌ها** و بیشینهٔ زمان
را ثبت می‌کند و در صورت شکست حتی یک آزمایش کد خروج غیرصفر می‌دهد.
همچنان فقط کلون **محلی و بدون شبکه** سنجیده می‌شود؛ زمان دانلود،
نصب Python و موفقیت واقعی کاربران نامعلوم است. این قابلیت در PR #145
در دست بررسی است، نه منتشرشده.

در CI پیشنهادی، چهار محیط Windows/Ubuntu و Job محدود macOS هرکدام
سه کلون **محلی مستقل** با `--repeat 3` اجرا می‌کنند. شکست حتی یک
آزمایش باعث شکست Job می‌شود و JSON نتیجهٔ همهٔ آزمایش‌ها را نگه می‌دارد.
زمان دانلود شبکه، نصب Python و اولین استفادهٔ واقعی کاربر همچنان
نامعلوم است؛ PR #145 هنوز ادغام نشده است.

## یادداشت‌های خودتان در پوشهٔ محلی جدا (اختیاری)

جست‌وجوی اول، **مستندات همین مخزن عمومی** را جست‌وجو می‌کند؛ هنوز حافظهٔ
شخصی شما نیست. برای نگهداری یادداشت‌ها، از داخل پوشهٔ کلون‌شده، یک
پوشهٔ تازه و خالی **بیرون از مخزن عمومی** بسازید:

```bash
python scripts/install.py --target ../my-private-brain
cd ../my-private-brain
```

با ویرایشگر محلی، فایل `02_WIKI/my-first-note.md` را در پوشهٔ جدید بسازید.
برای آزمایش، فقط یک جملهٔ ساختگی و غیرحساس با واژهٔ دقیق
`YOUR_UNIQUE_TERM` در آن بنویسید؛ سپس اجرا کنید:

```bash
python scripts/kb.py ingest
python scripts/kb.py search "YOUR_UNIQUE_TERM"
```

در خروجی باید مسیر `02_WIKI/my-first-note.md` دیده شود. نصب‌کننده مقصد
غیرخالی را رد می‌کند و پوشهٔ قبلی را بازنویسی نمی‌کند. مسیر مثال بیرون از
ریپوی کلون‌شده است، ولی پیش از واردکردن اطلاعات خصوصی بررسی کنید پوشهٔ
والد زیر کنترل Git یا همگام‌سازی عمومی نباشد. «محلی‌بودن» به‌تنهایی
به معنی رمزنگاری یا کنترل دسترسی سیستم‌عامل نیست. هیچ یادداشت خصوصی یا
کلید دسترسی را در Git عمومی منتشر نکنید. این راهنما اندازه‌گیری زمان
کامل نصب یا تضمین سازگاری با همهٔ هاست‌ها نیست.

## بررسی کامل برای مشارکت‌کنندگان

پیش از تغییر کد یا ارسال PR، به **پوشهٔ کلون منبع** برگردید و سلامت مخزن و مجموعهٔ کامل تست‌های آن را بررسی کنید. اگر مرحلهٔ اختیاری ساخت حافظهٔ شخصی را اجرا کرده‌اید، پوشهٔ نصب‌شده فقط تست مخصوص همان نصب را دارد و جایگزین مجموعهٔ تست‌های مخزن اصلی نیست. این بررسی‌ها پیش‌نیاز **مشارکت در توسعه** هستند، نه اولین جست‌وجوی کاربر:

```bash
cd ../second-brain-os
python scripts/health.py
python -m unittest discover -s tests
```

## کار با مهارت‌ها و ایجنت‌ها

```bash
python scripts/brain.py skills --query "research"
python scripts/brain.py start --goal "Organize my next research task"
```

CLI شناسه‌ای با پیشوند `SES-` می‌سازد که می‌توانید با دستورهای `status`، `add`، `done`، `trace` و `handoff` مدیریت کنید. بدون بازبینی Skills و برنامه، مسیر اجرای سخت‌گیرانه اجازه فراخوانی ابزار را نمی‌دهد. پایان موفق کار نیازمند شواهد، هندآف و تأیید انسان است.

برای جزئیات اجرایی انگلیسی [راهنمای CLI](CLI_VNEXT.md)، برای هدف جامع [چشم‌انداز محصول](PRODUCT_VNEXT.md) و برای نقش‌ها [تیم ایجنت‌ها](AGENT_TEAM_VNEXT.md) را بخوانید.

## قانون‌های اساسی

اطلاعات خصوصی در Git عمومی قرار نمی‌گیرند. ایجنت نمی‌تواند با ادعای خودش مجوز جدید بسازد، نتیجه کارش را مستقلاً تأیید کند یا Skill جدید را بدون بررسی به مجموعه اصلی ارتقا دهد. تغییر معماری ابتدا باید در محیط جدا شبیه‌سازی و تست شود و در صورت افت عملکرد، قابل بازگشت باشد.
